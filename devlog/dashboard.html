      Runner and pacing

      Not built

      The D3ngineering blueprint adds a scheduled runner that wakes every 15 minutes, takes the next ready item within budget gates (5-hour window, 40% of the weekly limit a day, an even weekly pace, an 80% weekly ceiling; ADR-0014 proposes slowing down in bands, Full, Normal, Low, Crawl and Stopped, instead of stopping), and a mode switch (normal, accelerate, auto, paused), Run next and Assign an agent on this page. None of it is built here yet: it waits on three decisions.

      Should the runner merge its own PRs?

      The blueprint merges a reviewed commit when CI is green and the tip has not moved. Voice Lab's rule today is that the owner merges every PR.

      Where should it run?

      The blueprint's runner is a Claude app task on a PC. Here it would be a Routine starting a cloud session. Whether a cloud session can read the usage windows the gates depend on is unverified; a probe run comes first.

      Its ceiling mode and permissions

      The highest mode allowed from the repository, and a signed list of what an unattended run may do.
